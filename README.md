# Data Engineering Interview Bank 🚀

**+40 preguntas profesionales + recursos para dominar Data Engineering**

---

## 📌 ¿Qué es esto?

Repositorio completo de **preguntas de Data Engineering** cubriendo SQL, PySpark, System Design, Cloud, Data Modeling, Orchestration y Streaming.

**Diseñado para:**

- ✅ Prepararte para entrevistas (Junior → Mid → Senior level)
- ✅ Refrescar conocimientos (seniors)
- ✅ Aprender patterns reales (producción)
- ✅ GitHub contributions

**Cobertura (hasta el momento):**

- SQL (Window Functions, Optimization, Data Quality)
- PySpark (Architecture, Performance, I/O)
- System Design (ETL, Warehouse, Real-Time, CDC, Lineage)
- Python/DSA (Strings, Collections, Generators, Decorators)
- Cloud (AWS, GCP, Azure, Multi-Cloud, Cost, Security)
- Data Modeling (Star Schema, SCD, Normalization)
- Orchestration (Airflow, dbt, Patterns)
- Streaming (Kafka, Windowing, Lambda vs Kappa)

## 🎯 Cómo Usar Este Repositorio

1. Comienza con **SQL** (fundamentals)
2. **Python/DSA** (language skills)
3. Luego **PySpark** (core tool)
4. **System Design** (ver el big picture)

### Para Seniors

1. **System Design** (detalles arquitectónicos)
2. **Orchestration** (production patterns)
3. **Streaming** (real-time systems)
4. **Cloud** (strategic decisions)

## 📖 Cómo Estudiar Cada Pregunta

Cada pregunta sigue este patrón:

**TL;DR (30 seg)**  
├─ Qué es  
├─ Por qué importa  
└─ Principio clave

**Concepto (5 min)**  
├─ Definición clara  
├─ Analogy / memory trick  
└─ Cuándo / dónde aplica

**Explicación técnica (10 min)**  
├─ Diagrama  
├─ Código  
└─ Real-world example

**Errores comunes (2 min)**  
└─ Qué no hacer en entrevista

**Preguntas de seguimiento (2 min)**  
└─ Questions que podrían hacer

**Tiempo total:** 15–20 minutos profundos

**Tip:** Después de leer, explica el concepto en voz alta. Eso es lo que harás en entrevista.

### 🛠️ Cómo Contribuir

#### 1. Fork este repositorio

```
git clone https://github.com/tu-usuario/data-engineering-interview-bank.git
cd data-engineering-interview-bank
git checkout -b mi-contribucion
```

#### 2. Sigue el Formato

Cada pregunta debe ser un archivo `.md` con esta estructura:

```
**Título Claro**
**Tags:** #tag1 #tag2 #tag3 #real-interview
**Dificultad:** Junior | Mid | Senior

**TL;DR**
2–3 líneas ultra-concisas. Qué es + por qué importa + principio clave.

**Concepto Core**
- Qué es
- Por qué importa
- Principio clave

**Memory Trick**
Frase memorable para recordar.

**Cómo explicarlo en entrevista**
4 pasos claros. Cómo explicarías esto a un entrevistador.

**Código / Ejemplos**
Ejemplos reales, ejecutables si es posible.

**Errores Comunes en Entrevista**
Error: X
→ Solución: Y

**Preguntas de Seguimiento**
"Pregunta?"
Respuesta corta.

**References**
Link
```

#### 3. Checklist Antes de PR

- [ ] Título descriptivo
- [ ] TL;DR < 100 palabras
- [ ] Mínimo 1 ejemplo de código
- [ ] Real-world case study incluido
- [ ] References activos
- [ ] Explica como si fuera entrevista
- [ ] Proofread (sin typos)

#### 4. Ejemplos de Contribuciones Bienvenidas

✅ BIENVENIDO:  
├─ Nueva pregunta en sección existente (Streaming, System Design)  
├─ Mejorar explicación (más clara, mejor ejemplo)  
├─ Agregar casos reales (tu experiencia)  
├─ Corregir errores (typos, code bugs)  
└─ Traducir a español (si está en inglés)

❌ NO SE ACEPTA:  
├─ Cambios estructurales sin discusión  
├─ Spam o auto-promoción  
├─ Contenido sin fuentes  
└─ Preguntas out-of-scope (no data engineering)

#### 5. Proceso PR

1. **Fork** → **Rama** → **Commit** → **Push**
2. **Pull Request** con descripción clara
3. Se revisa (24–72h)
4. Feedback / Merge
5. ¡Crédito en README!
